The `dev` command starts the OpenSya development runtime.

It automatically:

- Discovers the application structure
- Generates the backend runtime
- Starts the NestJS development server
- Starts the Nuxt development server
- Watches filesystem changes
- Regenerates the runtime automatically

::callout{color="primary" icon="i-lucide-play"}
The development runtime is fully convention-driven and automatically orchestrated by OpenSya.
::

## Basic Usage

::code-group

```bash [pnpm]
pnpm opensya dev
```

```bash [yarn]
yarn opensya dev
```

```bash [npm]
npx opensya dev
```

```bash [bun]
bun opensya dev
```

::

This starts both the backend and frontend runtimes in development mode.

## Development Runtime

When the development server starts, OpenSya:

1. Discovers the filesystem structure
2. Generates the backend runtime
3. Registers controllers, services and models
4. Starts the NestJS runtime
5. Starts the Nuxt runtime
6. Watches for filesystem changes

```txt [Development Lifecycle]
Filesystem Discovery
        ↓
Runtime Generation
        ↓
Backend Startup
        ↓
Frontend Startup
        ↓
Watch Mode
```

::callout{color="info" icon="i-lucide-refresh-cw"}
The backend runtime is regenerated automatically when files change.
::

## Watch Mode

By default, OpenSya watches the filesystem and reloads the runtime automatically.

```bash [Terminal]
pnpm opensya dev --watch
```

Short syntax:

```bash [Terminal]
pnpm opensya dev -w
```

Watch mode is enabled by default.

This allows the runtime to react automatically when controllers, services, models or other runtime files are modified.

## Run Server Only

Start only the backend runtime.

::code-group

```bash [pnpm]
pnpm opensya dev --server
```

```bash [yarn]
yarn opensya dev --server
```

```bash [npm]
npx opensya dev --server
```

```bash [bun]
bun opensya dev --server
```

::

Useful for API-only development workflows.

## Run Client Only

Start only the frontend runtime.

::code-group

```bash [pnpm]
pnpm opensya dev --client
```

```bash [yarn]
yarn opensya dev --client
```

```bash [npm]
npx opensya dev --client
```

```bash [bun]
bun opensya dev --client
```

::

Useful for frontend-only workflows or UI development.

## Custom Host

You can specify the host to listen on.

```bash [Terminal]
pnpm opensya dev --host 0.0.0.0
```

Short syntax:

```bash [Terminal]
pnpm opensya dev -h 0.0.0.0
```

This is useful for Docker environments, local network access or remote development.

## Generated Runtime

During development, OpenSya generates the backend runtime automatically inside:

```txt
.opensya/server/
```

This generated runtime is then executed automatically by the development server.

::callout{color="warning" icon="i-lucide-folder-code"}
Generated files inside `.opensya/` should not be edited manually.
::

## Filesystem-driven Development

OpenSya watches runtime directories such as:

```txt [Runtime Directories]
server/controllers/
server/services/
server/database/
server/guards/
server/locales/
client/pages/
client/components/
client/plugins/
```

Changes are detected automatically and reflected in the running application.

## Philosophy

The `dev` command is designed to provide a fast and scalable development experience for modern recruitment platforms.

Instead of manually wiring runtimes and restarting services, OpenSya continuously regenerates and orchestrates the application from filesystem conventions.
