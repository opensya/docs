The `cleanup` command removes generated OpenSya files and cached runtime artifacts.

It helps reset the generated runtime environment and clean temporary build outputs.

::callout{color="primary" icon="i-lucide-trash-2"}
The `cleanup` command only removes generated files. Your application source code is not affected.
::

## Basic Usage

::code-group

```bash [pnpm]
pnpm opensya cleanup
```

```bash [yarn]
yarn opensya cleanup
```

```bash [npm]
npx opensya cleanup
```

```bash [bun]
bun opensya cleanup
```

::

## What Gets Cleaned

The command removes generated runtime files such as:

```txt [Generated Runtime]
.opensya/
```

This may include:

```txt [Generated Files]
.opensya/
├── server/
├── client/
├── tsconfig.server.json
├── tsconfig.client.json
└── generated typings
```

It also removes cached runtime artifacts generated during development or build workflows.

## Example Output

```txt [CLI]
✓ Cleanup complete!
```

## Why Use Cleanup

The `cleanup` command is useful when:

- Resetting the generated runtime
- Fixing corrupted generated files
- Clearing runtime caches
- Debugging build issues
- Starting from a clean environment
- Preparing CI workflows

Example:

```bash [Terminal]
pnpm opensya cleanup
```

Then regenerate the runtime:

```bash [Terminal]
pnpm opensya prepare
```

## Runtime Regeneration

After cleanup, OpenSya regenerates runtime files automatically during:

- `opensya dev`
- `opensya prepare`
- `opensya build`

This means generated files are always reproducible from the filesystem structure.

::callout{color="info" icon="i-lucide-refresh-cw"}
OpenSya can fully regenerate its runtime from filesystem conventions.
::

## Safe Cleanup

The cleanup process only targets generated artifacts.

Your application source directories remain untouched:

```txt [Safe Directories]
server/
client/
opensya.config.ts
.env
package.json
```

::callout{color="warning" icon="i-lucide-shield-check"}
The `cleanup` command does not remove application source code.
::

## Internals

Internally, the command:

1. Loads the OpenSya configuration
2. Resolves the output directory
3. Removes generated runtime directories
4. Clears runtime caches
5. Resets generated artifacts

```txt [Cleanup Lifecycle]
Load Configuration
        ↓
Resolve Output Directory
        ↓
Remove Generated Files
        ↓
Clear Runtime Cache
        ↓
Clean Runtime State
```

## Philosophy

The `cleanup` command exists to keep the OpenSya runtime reproducible and deterministic.

Instead of manually deleting generated files and caches, OpenSya provides a dedicated command to safely reset the generated runtime environment.
