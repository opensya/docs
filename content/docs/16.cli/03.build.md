The `build` command generates a production-ready OpenSya application.

It prepares and builds both runtimes:

- The backend runtime powered by NestJS
- The frontend runtime powered by Nuxt

::callout{color="primary" icon="i-lucide-package-check"}
The `build` command generates optimized production artifacts for deployment.
::

## Basic Usage

::code-group

```bash [pnpm]
pnpm opensya build
````

```bash [yarn]
yarn opensya build
```

```bash [npm]
npx opensya build
```

```bash [bun]
bun opensya build
```

::

This command builds both the backend and frontend runtimes.

## What Happens During Build

During the build process, OpenSya:

1. Discovers the application structure
2. Generates the backend runtime
3. Compiles controllers, services, models and guards
4. Generates runtime typings
5. Builds the Nuxt frontend
6. Produces production-ready artifacts

```txt [Build Pipeline]
Filesystem Discovery
        ↓
Runtime Generation
        ↓
Backend Compilation
        ↓
Frontend Build
        ↓
Production Output
```

## Build Server Only

Build only the backend runtime.

::code-group

```bash [pnpm]
pnpm opensya build --server
```

```bash [yarn]
yarn opensya build --server
```

```bash [npm]
npx opensya build --server
```

```bash [bun]
bun opensya build --server
```

::

This is useful for backend-only deployments or API services.

## Build Client Only

Build only the frontend runtime.

::code-group

```bash [pnpm]
pnpm opensya build --client
```

```bash [yarn]
yarn opensya build --client
```

```bash [npm]
npx opensya build --client
```

```bash [bun]
bun opensya build --client
```

::

This is useful for frontend-only deployments or static hosting workflows.

## Production Output

After a successful build, OpenSya generates production artifacts for deployment.

The backend runtime is generated automatically from the `server/` directory while the frontend runtime is built through Nuxt.

OpenSya handles runtime orchestration automatically during the build process.
::

## Deployment

Once the application is built, the generated artifacts can be deployed to your infrastructure.

OpenSya is designed for self-hosted and fully owned deployments.

This allows teams to keep control over:

* Infrastructure
* Runtime configuration
* Deployment strategy
* Data ownership

## Philosophy

The `build` command transforms a convention-driven OpenSya application into a deployable production runtime.

Instead of manually wiring backend and frontend applications together, OpenSya generates and orchestrates the infrastructure automatically.
