The `prepare` command generates and prepares the OpenSya runtime without starting the development server or building production artifacts.

It is mainly used internally by other commands such as:

- `dev`
- `build`

but can also be executed manually.

::callout{color="primary" icon="i-lucide-cpu"}
The `prepare` command generates the runtime structure used by OpenSya.
::

## Basic Usage

::code-group

```bash [pnpm]
pnpm opensya prepare
````

```bash [yarn]
yarn opensya prepare
```

```bash [npm]
npx opensya prepare
```

```bash [bun]
bun opensya prepare
```

::

This prepares both backend and frontend runtimes.

## What Happens During Prepare

During preparation, OpenSya:

1. Discovers the filesystem structure
2. Generates the backend runtime
3. Registers controllers, services and models
4. Generates runtime typings
5. Prepares runtime metadata
6. Creates the generated runtime inside `.opensya/`

```txt [Prepare Lifecycle]
Filesystem Discovery
        ↓
Runtime Generation
        ↓
Type Generation
        ↓
Runtime Registration
        ↓
Prepared Runtime
```

The `prepare` command does not start the development server or build production artifacts.
::

## Generated Runtime

The generated backend runtime is written inside:

```txt
.opensya/server/
```

This runtime is then used by:

* `opensya dev`
* `opensya build`

Generated files may include:

```txt [Generated Files]
.opensya/
├── server/
├── client/
├── tsconfig.server.json
└── tsconfig.client.json
```

Generated files inside `.opensya/` should not be modified manually.
::

## When to Use Prepare

The `prepare` command can be useful for:

* CI pipelines
* Runtime generation
* Typing generation
* IDE integrations
* Pre-build workflows
* Runtime debugging

Example:

```bash [Terminal]
pnpm opensya prepare && pnpm opensya build
```

## Runtime Discovery

The prepare step scans directories such as:

```txt [Runtime Directories]
server/controllers/
server/services/
server/database/
server/guards/
server/locales/
client/pages/
client/components/
client/plugins/
```

OpenSya then transforms the filesystem structure into an executable runtime architecture.

## Philosophy

The `prepare` command exists to separate runtime generation from runtime execution.

Instead of manually wiring backend infrastructure and generated files, OpenSya automatically prepares a complete runtime layer from filesystem conventions.
